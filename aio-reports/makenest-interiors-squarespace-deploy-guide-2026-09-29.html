Sources: site inventory September 25, 2026; deployment design and purchase-page check September 29, 2026. This is a proposed installation sequence. JSON-LD is structured code describing your business and pages; a canonical URL is a page’s preferred public address.

Squarespace path: sitewide Code Injection for approved business corrections; Advanced → Page Header Code Injection for each service page. The purchase page describes WordPress; the preparation steps below cover Squarespace access, plan support, and the deployment commitment.

  1. Complete your validation page and send the reply. Then review the completed FAQ batch and send Q# edits or “ship as-is.”
  2. Have the October 6/7 pages live with approved visible copy and final canonical URLs. Confirm Squarespace account access, plan support, and the deployment commitment with Apollo.
  3. Book your 30-minute Zoom deploy session after those preparations are complete.
  4. On the call, save existing sitewide and homepage Code Injection for rollback. Inspect rendered JSON-LD and IDs. Remove the invalid handwritten homepage LocalBusiness block and reconcile Squarespace’s generated business identity. Prepare a replacement only if needed; avoid conflicting business entities.
  5. Prepare each Service block with the actual canonical URL and matching visible service text. Commercial uses /commercial after your October 7 content refresh. Publish approved FAQ answers visibly before preparing matching FAQPage code. No Review or AggregateRating for self-controlled reviews; no FAQ rich-result promise.
  6. Parse each final JSON block, check Schema.org vocabulary, and use Google Rich Results Test only for eligible features before installation. Never install placeholder tokens or code for a page that is not live.
  7. Install approved business corrections sitewide. On each matching live page, use Advanced → Page Header Code Injection for only that page’s Service or FAQ block.
  8. Inspect rendered source for duplicate IDs and canonical URLs; check mobile and desktop output and record what went live. If a change fails, restore the saved injection code or remove the new page block, recheck, and record the reversal.
  9. Record any separately approved client-hub, title, meta, alt-text, or placeholder cleanup as individual site changes. Change search exposure only with your explicit approval.
  10. Record the deployment date and schedule one re-measurement of the frozen 12-question set 30 days after execution.
